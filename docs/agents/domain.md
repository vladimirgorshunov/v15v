# Domain Docs

This repository uses a single-context layout:
- `GLOSSARY.md` at the repository root.
- Architecture decision records under `docs/adr/`.

Before exploring, read the glossary and ADRs relevant to the work.
If they do not exist, proceed silently; do not create placeholders.
Domain-modeling workflows create them when terms or decisions are resolved.

Use the glossary's vocabulary in issue titles, proposals, code, and tests.
Avoid synonyms the glossary explicitly rejects.
If a needed concept is missing, reconsider it or note the gap for domain modeling.

Explicitly flag proposals that contradict an existing ADR, identifying the ADR
and explaining why reopening the decision is warranted.
